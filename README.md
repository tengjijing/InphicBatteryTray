# Inphic 鼠标电量托盘

[**中文**](README.md) | [English](README.en.md)

给无线鼠标加一个**任务栏电量显示**。支持英菲克（INPHIC）的 **IN10**（设备主动上报）与 **IN9**（Feature Report 主动查询）两代，以及瓦尔基里 **VK M3 lite**（厂商通道查询，本次新增）。

不修改原厂驱动、不注入原厂软件、不写入设备——只是监听鼠标本来就每 2 秒主动发出的电量报告，然后画在托盘上。

## 为什么做这个

原厂配置工具 `INPHIC HUB` 只在它自己的界面里显示电量，而且必须打开软件、点进设备页才看得到。托盘不显示电量，关掉程序就什么都不知道了。

Windows 自带的"蓝牙设备电量"对 2.4G 接收器无效，所以只能自己做一个。

## 快速开始

### 方式一：直接用

1. 下载 `InphicBatteryTray.exe`
2. 放到一个固定目录（比如 `%LOCALAPPDATA%\InphicBatteryTray\`）
3. 双击运行，托盘出现图标
4. 右键图标 → 勾选「开机自动启动」

> 如果双击后**什么都没出现**，先确认 exe 放在哪：某些目录（同步盘、安全软件的隔离目录、带特殊 ACL 的文件夹）会让 Windows 拒绝程序注册托盘图标，表现就是「双击没反应」。把 exe 挪到 `%LOCALAPPDATA%`、`C:\Users\<你>\` 这类普通目录再试。
> 图标可能被 Windows 11 折叠进 `^` 溢出区；电量读数同时写进 exe 同目录的 `tray.log`。

> 建议不要放在原厂软件目录里——卸载或重装 INPHIC HUB 时可能被一起删掉，开机自启就失效了。

## 工作原理

### 传输层

原厂软件是纯用户态程序，用 **hidapi** 走 HID Output/Input Report，**没有内核驱动**。本工具直接用 Windows 的 `hid.dll` + `setupapi.dll` 枚举和读取，连 `hidapi.dll` 都不需要。

关键点：**用 `FILE_SHARE_READ | FILE_SHARE_WRITE` 共享方式打开**。HID 输入报告会复制给所有打开该接口的句柄，所以本工具可以和原厂软件**同时运行**，互不干扰。

### 电量报告格式（已实测）

电量走在 `Usage Page 0x000A` 那个接口上（注意不是 64 字节的厂商通道），固定 **5 字节**：

```
偏移  0        1              2         3        4
      0x03     设备类型码      子命令     设备号    数据
```

| 字节 | 含义 |
|------|------|
| `[0]` | 固定 `0x03`（Report ID） |
| `[1]` | 设备类型码：`0x95` / `0x90` / `0x93` / `0x99` / `0x98` / `0x73` |
| `[2]` | 子命令：`0x10` 连接/设备号、`0x20` 状态、`0x40` **电量**、`0x50` 充电 |
| `[3]` | 设备号 `1..7` |
| `[4]` | 数据，电量时是 `0..100` |

实测样本：

```
03 98 40 01 64     →  设备类型 0x98，电量报告，设备 #1，电量 0x64 = 100%
```

### 上报规律（已实测）

| 项目 | 实测值 |
|------|--------|
| 方向 | **设备主动推送**，主机全程不发查询 |
| 周期 | **≈2000 ms**，抖动 ±60ms |
| 精度 | 整数百分比（1% 粒度），**无小数、无电压/ADC 字段** |
| 关机行为 | **直接静默**，不发任何"我要下线"通知 |
| 其它子命令 | 本机所有场景（开关机、插拔）均未触发过 `0x10/0x20/0x50` |

最后两条是离线检测只能靠**超时**的原因：设备不会告诉你它走了，只能靠"沉默 8 秒"推断。

### 为什么是 8 秒

上报周期 2 秒，8 秒 = 连续漏掉 4 帧，不会因为一次抖动误判，也不至于关机后太久才变灰。

### 连接方式怎么判断

不是问设备，是**看 HID 接口路径**：蓝牙设备走 `BTHENUM` 路径，其余判为 USB。这和厂商自己的做法一致（原厂软件靠 VID 区分不同连接模式）。

### 图标渲染

托盘图标是运行时用 GDI+ 逐像素画的，不是预先做好的图片：

1. 把 `MouseIcon.png` 缩放到系统实际图标尺寸（通常 16×16）
2. 找 alpha 边缘，把最外圈强行描成深色实线——16px 下描边本来只有半个像素，不这样会糊成一团
3. 识别"绿色主体"像素（`G - R > 45 && G - B > 45`），按电量高度替换成状态色或灰色
4. 描边、滚轮、顶部按键保持原色

这样即使只有 16×16，也能看出是鼠标而不是一个色块。

### IN9 系列（另一套协议）

IN9 和 IN10 **完全不通用**，连传输方式都不一样：

| 项目 | IN10 | IN9 |
|---|---|---|
| 传输 | Input Report，设备主动推 | **Feature Report**（`HidD_SetFeature` / `HidD_GetFeature`） |
| 报告 ID | `0x03`（状态）/ `0x04`（配置） | **`0x0C`** |
| 帧长 | 5 字节 | **33 字节** |
| 电量怎么来 | 被动收，每 2 秒一帧 | **主机发 `0x20` 主动查** |
| 电量位置 | 第 5 字节 | 响应 `buf[0x12]` |
| VID/PID | `1D57` / `045E` 共 9 组 | `248A:5B2E`（有线）/ `248A:5B2F`（2.4G） |

IN9 帧格式：

```
[0]     0x0C        报告 ID
[1]     0x01        固定
[2]     命令码      0x20 = 查电量   0xF0 = 握手
[3]     0x00
[4]     序号（自增）
[5..]   载荷
```

- 握手：`0C 01 F0 00 <seq> 01 01 FF`（只发不收）
- 查电量：`0C 01 20 00 <seq> 00 00` → 等 10ms → 读回 33 字节

响应布局：

| 偏移 | 含义 |
|---|---|
| `[2]` | `0x20` 命令回显 |
| `[6]` | `!= 0` 才算有效响应 |
| `[8..0x0B]` | 型号魔数（如 `"M909"`） |
| `[0x0F]` | IC 型号 |
| `[0x12]` | **电量 0–100** |
| `[0x13]` | `2` = 充电中 |
| `[0x15]` | 在线标志 |

> 帧格式与响应布局来自衍生项目 [InphicBatteryTray-IN9](https://github.com/MRXie-zf/InphicBatteryTray-IN9)，由原厂 `Inphic IN9 GM.exe` 逆向并在 IN9 升级版上实机验证。

设备定位：`VID == 248A` 且 **Feature 报告长度 ≥ 33** 的接口（不是 MI_02）。两代扫描逻辑互不干扰，同时插着也能各自识别。

## 瓦尔基里 VK M3 lite（本仓库新增的第三套协议）

本仓库在原版基础上加了一条 VK 通道，其余行为（图标渲染、详情浮层、开机自启、离线判定）与原版完全一致。

### 设备与通道

| 项目 | 值 |
|------|-----|
| 2.4G 接收器 | `249A:5C2F`（官方配置里 dev_id `M220`，产品名 `Wireless-Receiver`） |
| 有线 | `248A:5C2E` / `248A:5D2E` / `248A:5E2E` |
| 接口 | 复合设备的 **MI_02** 厂商通道（`UsagePage 0x0001 / Usage 0x0000`） |
| 报告长度 | Input 33 / Output 33 / **Feature 0**（所以不能像 IN9 那样用 Feature 查询） |

### 帧格式（实测）

同一个接口上**主机发 Output Report、设备回 Input Report**，都是 33 字节：

```
[0]     0x00       报告 ID（Windows 发送要带这个前置 0；macOS 版不需要）
[1]     命令码
[2]     状态       0x00 成功 / 0x02 设备休眠（此时 [3] = 0xFF）
[3]     0x01       固定
[4]     载荷长度
[5..]   载荷
[32]    校验和     = sum(字节 5..31) & 0xFF
```

查电量只要发一帧：`[0]=0x00, [1]=0x10`，其余全 0（空载荷 + 校验和 0 天然成立）。

`0x10` 响应载荷共 11 字节：

| 载荷偏移 | 含义 | 实测值 |
|---|---|---|
| `[0..3]` | 型号串 | `M220` |
| `[4..7]` | 版本 / 固定 | `84 01 11 01` |
| `[8]` | **充电标志** | `1` 充电中 / `0` 未充电 |
| `[9]` | **电量百分比** | `0x3A` = 58%，`0x64` = 100% |
| `[10]` | 固定 | `0x01` |

实测样本：

```
4D 32 32 30 84 01 11 01 00 3A 01   →  M220，未充电，58%
4D 32 32 30 84 01 11 01 01 64 01   →  M220，充电中，100%
```

> **插着线时的 100% 不是真实容量。** 实测同一只鼠标：充电中设备一直回 `… 01 64 01`（100%），
> 拔线后第一帧就是 `… 00 40 01` = **64%**。也就是说带电时电量字段会顶到 100%，跟真实剩多少无关。
> 所以程序在充电标志为 `1` 时**不覆盖电量**，只把状态标成「充电中」，托盘继续显示最后一次
> 非充电时的真实读数（悬停提示会写「充电中，设备此刻上报的 100% 不作数」）。

### 和官方软件共存

同样用 `FILE_SHARE_READ | FILE_SHARE_WRITE` 打开 MI_02，可以和 `VK M3 Series.exe` 同时运行。踩过两个坑，都已规避：

1. **同一句柄上挂着阻塞 `ReadFile`，`WriteFile` 会永久卡住** → 开两个句柄，一个只读收帧、一个只写发帧。
2. **`HidD_SetOutputReport` 返回成功但设备不响应** → 必须用 `WriteFile` 发完整的 33 字节（含报告 ID）。

### 不要盲扫命令码

这个协议的 `0x01–0x0F` 是**写命令段**：`0x03` 写 DPI 六档、`0x09` 写六键映射。用全 0 载荷去扫会把鼠标配置清空（DPI 掉到极低、所有按键失效）。开发中踩过这个坑，按原值重写即恢复：

- 六键：`00 09 00 01 0F` + `10 01 00 10 02 00 10 04 00 10 08 00 10 10 00 40 01 00`（左 / 右 / 中 / 前进 / 后退 / DPI 循环）
- DPI 六档：`00 03 00 01 25 01` + 6 组 `(Xlo Xhi Ylo Yhi)` = `10 00 10 00 18 00 18 00 28 00 28 00 64 00 64 00 a0 00 a0 00 dc 00 dc 00`（800 / 1200 / 2000 / 5000 / 8000 / 11000，即 raw × 50）

只读命令 `0x10–0x17`、`0x20` 可以安全调用。

### 轮询频率

VK 协议没有主动上报，只能主机查询：程序每 **4 秒**发一次 `0x10`（`VkQueryLoop` 里的 `Thread.Sleep(4000)`），离线判定沿用原来的 8 秒超时，相当于漏 2 帧才判离线。原版 IN10 是设备 2 秒推一次，两条通道互不影响。

### 轮询会把鼠标吵醒、多耗电吗

实测（静置 40 秒一帧都不发，再读一次）：设备照样立刻回 `status=0x00`，根本没进休眠；再静置 25 秒仍然在线（只有载荷第 11 字节从 `01` 变成 `00`）。说明在 2.4G 接收器在线时它本来就不睡，4 秒一帧的查询没有「把设备唤醒」的额外代价 —— 每帧 33 字节，占空比可以忽略。

对比两条原版通道：IN9（`248A:5B2E` / `5B2F`）的主机查询间隔是 `Thread.Sleep(2500)`（见 `src/InphicBatteryTray.cs:936`），比这里的 4 秒还频繁；IN10 则是设备每 2 秒主动推一次，主机一帧都不发。

## 隐私

本工具**只读**，并且明确避开用户输入：

- ✅ 读取：IN10 状态通道（`Usage Page 0x000A`）上的推送电量
- ✅ 查询：IN9 的 Feature Report 电量命令（`0x20`，只读，不改任何设置）
- ✅ 查询：VK 的 MI_02 通道 `0x10` 读型号/电量（只读；`0x01–0x0F` 是写命令段，代码完全不碰）
- ✅ 读取：HID 元数据（VID/PID、产品名、报告长度）
- ❌ **不读取**任何 `Usage Page 0x0001`（Generic Desktop）接口——那是键盘和鼠标本体，上面跑的是按键和移动数据
- ❌ 不修改设备配置（DPI / 灯光 / 按键映射一律不碰）
- ❌ 不联网，无遥测

这也是开发过程中调试探针的硬约束：所有抓包脚本都显式过滤掉了键盘/鼠标接口。

## 已知限制

1. **型号覆盖**：IN10 在 `Inphic KP 8K` 上实测通过；IN9 按升级版实测协议实现（`248A:5B2E` / `248A:5B2F`）；VK 在 `249A:5C2F`（VK M3 lite + 2.4G 接收器）上实测通过。其余型号（IN10 Pro / IN6 / 其它 VK）未验证，协议若有差异可能读不到电量。
2. **电量精度就是 1%**，硬件层面没有小数、没有电压、没有健康度。想显示 `87.3%` 只能靠软件插值造假，本项目没做。
3. **无法配置上报频率**。IN10 的 2 秒是固件定的，IN9 的 2.5 秒是软件定的；两代都没有"设置上报间隔"的命令。
4. **离线靠超时猜测**（8 秒），因为设备关机时不发通知。如果鼠标只是短暂休眠（不是关机），也可能被误判成离线。
5. 16×16 图标下角标和细节会糊，这是托盘图标的物理上限。

### 读不到电量？

程序会在同目录写 `tray.log`（超过 512KB 自动换新），记录枚举到的接口、收发字节与解析结果。遇到问题把文件贴到 issue 里即可定位。
